# Brasília Military Middle School 2017's Library - Based on KACTL

This repo hosts our library, based on the KACTL, [KTH](https://en.wikipedia.org/wiki/KTH_Royal_Institute_of_Technology)'s ICPC team reference document.
It is made for use in ICPC-style programming competitions.

See [kactl.pdf](./kactl.pdf) for the final, browsable version, and [content/](./content/) for raw source code.

## Code Aspirations and Style

Code should be: useful, short, fast, tested, and if relevant, easy to modify.
It should *not* be overly generic or readable, since it is manually typed and that just adds overhead.
Due to space issues (page limit in ICPC), we also exclude algorithms that are very common/simple (e.g., Dijkstra), or very uncommon (general weighted matching).

KACTL uses a relatively terse coding style, with a handful of macros/typedefs defined in the
[template](./content/contest/template.cpp) that help shorten the code.
Line width is 63 chars, with tabs for indentation (tab = 2 spaces in the pdf).

Each algorithm contains a header with the author of the code, the date it
was added, a description of the algorithm, its testing status, and preferably also
source, license and complexity.

## PDF Structure

kactl.pdf is ideally to be kept to 25 pages + cover page. You can check out what's excluded by default by running `make showexcluded`

`content/kactl.tex` is the main file of KACTL, and can be edited to change team name, logo, syntax highlighting, etc.
It imports `chapter.tex` files from each of the `content/` subdirectories, which define the contents of each chapter.
These include source code, text and math in the form of LaTeX.
To add/remove code from a chapter, add/remove a corresponding `\kactlimport` line from the `chapter.tex` file.
For nicer alignment you might want to insert `\hardcolumnbreak`, `\columnbreak` or `\newpage` commands,
though this is usually only done before important contests, and not on the main branch.
The algorithms that are not included in the pdf are left commented out in `chapter.tex`.

To build KACTL, type `make kactl` (or `make fast`) on a \*nix machine -- this will update `kactl.pdf`.
(Windows might work as well, but is not tested.) `doc/README` has a few more notes about this.

Also, you should take advantage of the hashing when typing in these algorithms. Each
algorithm has a 6 character MD5 hash in the upper right. This hash can be
generated by using `hash.sh` or the `:Hash` command from the `.vimrc`. The
hashing ignores whitespace and comments. Also, we've added hashes for each set of code inside keys (`{}`) as a comment on the line after the closing `}`. This allows you to easily check if you've typed in a code block correctly, even if you haven't typed in the whole algorithm yet.

## Contributing

We have a [TODO](./TODO) file with some things we want to do. Please keep it updated, as well as this documentation in case anything changes.

To add a new algorithm implementation, add a new file in the related subdirectory under `content/`, and add a `\kactlimport` line for it in the subdirectory's `chapter.tex` file. The file should have the appropriate header information (see other files for examples). You may use the macros defined at the [template](./content/contest/template.cpp).

The code should compile and have been tested at some competitive programming problem (link it in the description header), preferably with no differences between the submission and repository code.

If you want to add a new content section, add a new subdirectory under `content/` with a `chapter.tex` file, and add a `\kactlchapter` line for it in `content/kactl.tex`. You can copy the structure of the other chapters.
